Key Privacy Mechanisms In Action

  • Consent Gating: Displaying granular cookie preferences banners before loading any non-essential trackers.
  • Sensitive Wellness Data Protection (Soulamore): Implementing full-screen, explicit opt-in confirmation dialogs before journaling. Wellness data is never processed for advertisement or shared with third parties.
  • Automated Data Rights Center: Accessible under account settings, allowing users to instantly download a CSV/JSON of their data or execute permanent database deletion commands completed within 30 days.
  • Email Marketing Protocols: Adhering to CAN-SPAM and CASL with physical corporate footer designations and functional one-click unsubscribes.

Audited Security Protections

To protect sensitive user records, we have remediated common vulnerabilities identified in security audits:

1. Insecure Direct Object Reference (IDOR) Mitigation

  • Opaque UUIDs: Replaced auto-incrementing integer IDs with high-entropy UUID v4 identifiers across all user data references.
  • Ownership Validations: Enforced backend database ownership validations on every API controller path to prevent cross-account modifications.

2. Session & Auth Hardening

  • HttpOnly, Secure Cookies: Session JWTs are stored in HttpOnly cookies with `SameSite=Strict` and `Secure` attributes, blocking token extraction via XSS.
  • Firebase App Check: Integrated reCAPTCHA Enterprise and device-attestation check tokens to prevent unauthorized script-based API queries.

3. Input Sanitization & XSS Safeguards

  • DOMPurify Filtering: Sanitized all user-generated content client-side and server-side to remove execution payloads.
  • Content Security Policy (CSP): Established strict header settings restricting external connect resources and inline scripting.

4. Abuse Shielding

  • API Rate Limiting: Implemented IP-based and User-ID-based rate limiters on login, registration, and feedback pathways to prevent credential stuffing and database scraping.
  • CSRF Protections: Configured CSRF header validation on all state-changing PUT/POST/DELETE API endpoints.
