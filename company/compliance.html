Audited Security Architecture

Following a rigorous security review, our technical system has been hardened against common operational vulnerabilities:

1. IDOR Safeguards (Insecure Direct Object Reference)

We have completely mitigated URL-enumeration vulnerabilities:

  • UUID v4 Implementation: Database entries (journal logs, confessions, bookings) are referenced using high-entropy random UUIDs instead of sequential integers.
  • Server-Side Ownership Validation: Every API endpoint enforces checks confirming that the authenticated session user matches the resource owner.

2. Session & Token Hardening

  • HttpOnly Cookie Storage: Authentication JWTs are stored using `httpOnly`, `Secure`, and `SameSite=Strict` cookies. This keeps credentials hidden from client-side JavaScript, rendering XSS token theft impossible.
  • Firebase App Check: Enforces server-side validation using reCAPTCHA Enterprise and device-attestation check tokens to prevent unauthorized script-based API requests to Firestore databases.

3. Input Sanitization & XSS Mitigation

  • DOMPurify Integration: User-generated content (including markdown inputs in journals) is passed through DOMPurify client-side and validated server-side to strip malicious script tags.
  • Content Security Policy (CSP): Configured to prevent execution of unauthorized external scripts.

4. Abuse Prevention & Rate Limiting

  • Brute Force Shielding: Login, signup, and feedback API pathways are protected by rate limiters (by IP and user ID), implementing exponential backoff.
  • Bot Mitigation: CAPTCHAs are active on public forms to block automated spam and credential stuffing.
