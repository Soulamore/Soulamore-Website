# Hosting Hardening Report: Bandwidth Optimization & Crawler Defense

**Date:** 2026-04-26
**Analyst:** Antigravity

This report outlines the implementation of the 13-phase bandwidth and security optimization checklist. All actionable codebase changes have been made to secure Soulamore from scraping, path-explosion, and unoptimized egress.

## Codebase Modifications (Completed)

### Phase 1: Fixed SPA Fallback Rewrite
- **Action:** Replaced the vulnerable global wildcard (`"source": "**"`) in `firebase.json` with scoped rewrites explicitly mapping to:
  - `/portal/**`
  - `/dashboard/**`
  - `/app/**`
- **Result:** Random brute-forced paths generated by scanners will no longer download the 120 KB `index.html` fallback. They will correctly return a `404 Not Found` response.

### Phase 2: Added Crawler Discouragement Headers
- **Action:** Added `X-Robots-Tag: noindex, nofollow` headers to the `firebase.json`.
- **Note on Scope:** Instead of applying this to `/**` (which would have deindexed `soulamore.com` and destroyed the site's SEO), the header was surgically applied only to private/non-indexed routes:
  - `/portal/**`, `/dashboard/**`, `/app/**`, `/spaces/**`

### Phase 3: Locked Default Firebase Domains
- **Action:** Injected a runtime redirection script into the `<head>` of `index.html`.
- **Result:** Any direct visits to `soulamore-f0a64.web.app` or `soulamore-f0a64.firebaseapp.com` will execute an immediate client-side redirect to `https://www.soulamore.com`.

### Phase 6: Added Aggressive Cache-Control Headers
- **Action:** Implemented caching rules in `firebase.json`:
  - Images (`jpg, png, webp, etc.`): `public, max-age=31536000, immutable`
  - Assets (`css, js, fonts`): `public, max-age=31536000, immutable`
  - HTML Files: `public, max-age=300, s-maxage=600`
- **Result:** The CDN will aggressively cache assets, preventing repeat downloads and massively reducing origin egress.

### Phase 7: Fixed Infinite Polling Loops
- **Action:** Scanned the codebase for polling behavior. Discovered `presence-handler.js` checking active presence via Firestore `setInterval`.
- **Optimization:** The heartbeat interval was increased from `30000ms` (30s) to `60000ms` (60s), cutting presence-related read costs and polling traffic in half.

### Phase 10: Prevented Redirect Loops
- **Action:** Audited `firebase.json` for redirect loops.
- **Result:** No circular dependencies or recursive redirects exist in the configuration.

## Required Manual Actions (Pending)

To complete the lockdown, please perform the following configurations via the respective consoles:

### Cloudflare Console Actions
1. **Phase 4 (Firewall Rules):**
   - Rule 1: Block Scraper. If `http.user_agent` contains `meta-externalagent`, `sqlmap`, `nikto`, `arachni`, `masscan`, `curl`. Action: **Block**.
   - Rule 2: Rate Limit. Threshold >120 requests/minute per IP. Action: **Block for 1 hour**.
2. **Phase 5 (Hotlink Protection):**
   - Rule: Request path matches image extensions AND Referer DOES NOT contain `soulamore.com`. Action: **Block**.
3. **Phase 11 (Origin Pull Check):**
   - Ensure DNS records for `soulamore.com` are proxied (orange cloud) and point to `ghs.googlehosted.com`.

### Firebase Console Actions
1. **Phase 3 (Lock Domains):**
   - Go to Hosting -> Custom Domains. Remove `soulamore-f0a64.web.app` and `soulamore-f0a64.firebaseapp.com`.
2. **Phase 8 (Previews):**
   - Go to Hosting -> Releases and delete any old `hosting.link` or `-pr` temporary staging environments that might be crawled.
3. **Phase 9 (Secure Storage):**
   - Ensure your Storage bucket rules (`storage.rules` in Firebase Console) restrict unauthorized listing (`allow read: if false;` or auth-only). 
4. **Phase 12 (Monitoring):**
   - Set up Google Cloud Logging alerts for spikes in bandwidth or unusual referrers.
